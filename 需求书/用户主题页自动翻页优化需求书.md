# 用户主题页自动翻页优化需求书

## 1. 背景

当前 `sehuatang-toolbox.user.js` 已经将用户主题页纳入自动翻页支持范围，但实际运行中，用户主题页的自动翻页体验和普通板块列表页不一致。

主要原因是用户主题页属于 `home.php` 空间页面，页面结构、URL 参数、主题行 DOM 结构和普通板块页不同。当前脚本虽然允许在用户主题页触发自动翻页，但加载后的处理流程仍大量复用板块页逻辑，导致预览刷新、内容插入、去重和状态统计不够稳定。

## 2. 目标

优化用户主题页的自动翻页功能，使它在体验上接近普通列表页，并避免因为 DOM 结构差异造成重复内容、预览错位、预览不刷新或状态统计不准确。

优化后的功能应满足：

- 用户主题页滚动到底部时，可以自动加载后一页。
- 手动点击“加载后一页”时，也能稳定追加下一页主题。
- 新加载的主题可以被预览功能识别。
- 如果自动预览已开启，新加载主题应按现有并发策略继续加载预览图。
- 不应重复插入已有主题。
- 不应把分页、表单、标题栏、空白节点等非主题内容重复插入页面。
- 用户主题页逻辑应和板块页、搜索页、收藏页分开处理，减少互相影响。

## 3. 当前问题

### 3.1 页面类型识别不完整

当前代码中存在多个和用户页相关的判断：

- `isUserThreadPage()`
- `isSpacePage()`
- `isMySpacePage()`
- `isMyfavoritePage()`

但 `getPageNameForScroll()` 没有明确返回用户主题页类型。用户主题页可能落入其他分支，也可能被默认当作板块页处理。

### 3.2 加载后处理缺少用户主题页分支

`processPageContent()` 当前主要处理：

- 搜索页
- 板块页
- 帖子页

用户主题页自动加载新内容后，没有明确执行用户主题页专属刷新逻辑，只能依赖 MutationObserver 间接触发 `refreshThreads()`，稳定性不足。

### 3.3 内容追加粒度过粗

当前 `appendNewContent()` 会 clone 目标容器下的所有 `childNodes`。在普通板块页中，这通常还能工作，但用户主题页可能包含：

- 分页节点
- 表单节点
- 空白文本节点
- 标题区
- 操作区
- 非主题列表内容

直接整体追加容易导致重复内容、结构错位和预览挂载异常。

### 3.4 预览挂载点和旧脚本逻辑不同

旧的用户主题页管理脚本中，预览通常挂在 `thread.link.parentElement` 下，更接近标题区域。

当前 toolbox 的通用预览逻辑会优先寻找整行主题节点，再将预览插入到整行后面。对于用户主题页，这种方式可能导致预览位置不符合页面结构。

## 4. 普通列表页和用户主题页的实现差异

### 4.1 普通板块列表页

普通板块页通常具备以下特点：

- 页面类型：`forum.php?mod=forumdisplay` 或 `forum-xxx-page.html`
- 主容器通常是 `#threadlist`
- 下一页链接通常可以通过 `.pg a.nxt` 获取
- 主题行结构相对稳定
- 加载后可以直接执行：
  - `refreshThreads()`
  - `loadAllPreviews()`
  - `dedupeThreadItems()`

### 4.2 搜索结果页

搜索页同样是主题列表，但多了板块筛选逻辑：

- 加载后需要重新执行 `applySearchFilter()`
- 未选中板块的帖子不能显示预览
- 预览加载前需要经过筛选判断

### 4.3 用户主题页

用户主题页属于空间页，通常具备以下特点：

- 页面类型：`home.php?mod=space&uid=xxx&do=thread&view=me&page=xxx`
- 需要保留 `uid`、`do`、`view`、`type`、`from` 等参数
- 主题行可能不完全等同于板块页主题行
- 不能简单 clone `#threadlist` 的全部子节点
- 加载后需要明确触发用户主题页的刷新、去重和预览逻辑

## 5. 功能需求

### 5.1 页面适配器

应新增页面适配器思路，将不同页面的翻页行为拆开：

- 板块页适配器
- 搜索页适配器
- 用户主题页适配器
- 收藏页适配器
- 帖子页适配器

每个适配器负责：

- 判断是否匹配当前页面
- 构建下一页 URL
- 获取当前页主题行
- 获取远程页主题行
- 追加新内容
- 执行加载后的刷新逻辑

### 5.2 用户主题页 URL 构建

用户主题页下一页 URL 应基于当前 `location.href` 构建，只修改 `page` 参数，不丢失其他参数。

示例：

```text
home.php?mod=space&uid=123&do=thread&view=me&page=2
```

如果当前 URL 存在 `type=reply`、`type=thread` 或 `from=space` 等参数，也应保留。

### 5.3 用户主题行提取

用户主题页应只提取真正的主题行，不应追加整个容器的所有子节点。

建议规则：

- 以包含 `viewthread` 或 `thread-` 链接的节点为候选。
- 候选节点必须能解析出 `tid`。
- 同一个 `tid` 只保留一个主题行。
- 优先保留包含标题链接的行。
- 排除工具栏、预览容器、分页、表单和页面外壳节点。

### 5.4 用户主题页内容追加

自动加载下一页后，应只追加新主题行。

追加时应：

- 在当前主题列表末尾插入页码分隔线。
- 为新追加的主题行标记 `data-shtx-autoload-page`。
- 跳过当前页面已经存在的 `tid`。
- 不追加分页节点、表单节点、工具栏节点。

### 5.5 加载后处理

用户主题页加载下一页成功后，应明确执行：

- 去重主题行。
- 刷新 `STATE.threads`。
- 更新主题数量状态。
- 如果自动预览开启并且预览处于展开状态，则继续加载新主题预览。
- 更新翻页状态。

不应只依赖 MutationObserver 兜底刷新。

### 5.6 预览位置

用户主题页预览应优先插入在标题区域下方，避免插到不合适的整行外部。

建议策略：

- 如果是用户主题页，优先使用标题链接父节点作为挂载点。
- 如果无法找到合适父节点，再回退到通用主题行挂载点。
- 避免在同一个主题下重复插入预览容器。

### 5.7 自动翻页触发

用户主题页应支持两种触发方式：

- 滚动接近页面底部时自动加载后一页。
- 点击工具栏中的“加载后一页”手动加载。

自动翻页仍只加载后一页，不恢复一次加载多页的行为。

## 6. 非功能需求

### 6.1 性能

- 不应一次性扫描或插入大量无关 DOM 节点。
- 新页解析应在离线 `document` 中完成，再批量追加必要节点。
- 图片预览仍应保持并发限制，避免 CPU 和内存压力过高。

### 6.2 稳定性

- 请求失败时不应破坏当前页面。
- 没有更多页面时应正确显示“没有更多”状态。
- 重复触发滚动事件时，不应并发加载同一页。

### 6.3 兼容性

- 不影响普通板块页、搜索页、收藏页、帖子页现有行为。
- 不影响搜索页板块筛选和预览联动逻辑。
- 不影响收藏页导出和预览功能。

## 7. 验收标准

### 7.1 用户主题页自动翻页

- 打开用户主题页后，滚动到底部能自动加载后一页。
- 点击“加载后一页”能加载下一页。
- 新主题只追加一次。
- 页面不会重复出现分页、标题栏、表单等非主题内容。
- 状态栏显示的主题数量会更新。

### 7.2 用户主题页预览

- 新加载主题可以显示预览图。
- 已有预览不会重复生成。
- 预览位置在标题区域下方或主题信息下方，不应跑到页面右侧或不相关区域。
- 自动预览关闭时，新加载主题不主动加载预览图。
- 手动展开预览后，新加载主题能补齐预览。

### 7.3 回归验证

- 板块页自动翻页正常。
- 搜索页自动翻页正常。
- 搜索页板块筛选后，未选中板块不显示预览。
- 收藏页预览不重复。
- 帖子页自动翻页不受影响。

## 8. 建议实现方案

建议新增或重构以下函数：

```text
getPageAdapter()
getUserThreadRows(root)
appendUserThreadRows(doc, page)
buildUserThreadNextUrl(page)
afterUserThreadAppend()
getUserThreadPreviewMountNode(link)
```

并调整：

```text
getPageNameForScroll()
appendNewContent()
processPageContent()
getPreviewMountNode()
```

核心原则是：用户主题页不要再默认当成板块页处理，而是拥有自己的翻页和预览适配逻辑。

## 9. 风险点

- 用户主题页可能存在不同 URL 形态，需要兼容 `uid` 缺失时从页面链接推断。
- 不同皮肤或不同版块可能导致主题行 DOM 不一致，需要提取逻辑足够保守。
- 预览挂载点调整可能影响收藏页或搜索页，因此应只对用户主题页启用专属挂载逻辑。

## 10. 后续开发建议

优先实现用户主题页适配器，不要继续在通用板块页逻辑中补条件。

开发顺序建议：

1. 明确 `isUserThreadPage()` 的页面类型返回。
2. 新增用户主题页主题行提取函数。
3. 新增用户主题页内容追加函数。
4. 加载后显式刷新主题和预览。
5. 调整用户主题页预览挂载点。
6. 做板块页、搜索页、收藏页回归测试。
