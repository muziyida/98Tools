# 收藏打开帖子并发收藏项目需求书

## 1. 项目背景

当前 `sehuatang-toolbox.user.js` 中已有“收藏打开帖子”功能。该功能会读取当前浏览器中已打开的帖子页记录，然后在弹窗中批量收藏这些帖子。

现有实现位于：

```text
openFavoriteDialog()
batchFavoriteOpened()
favoriteThread()
getOpenThreads()
```

当前批量收藏采用串行方式执行：一个帖子收藏请求完成后，等待固定延迟，再处理下一个帖子。该方式稳定但效率较低。当打开帖子数量较多时，完成全部收藏需要较长时间。

本次需求是将“收藏打开帖子”功能改造为并发执行，在不明显增加崩溃、封禁、请求失败风险的前提下，提高批量收藏速度。

## 2. 项目目标

将“收藏打开帖子”从串行收藏改为受控并发收藏。

目标效果：

- 多个帖子可以同时发起收藏请求。
- 并发数量可控，避免一次性请求过多导致浏览器卡顿或网站压力过大。
- 每个帖子仍能独立显示收藏结果。
- 总进度、成功数、已收藏数、失败数实时更新。
- 用户可以清楚知道任务正在进行、已完成或失败。
- 并发执行不影响当前打开帖子记录、清理记录、手动移除帖子等现有功能。

## 3. 当前功能分析

### 3.1 当前流程

当前流程如下：

1. `getOpenThreads()` 获取已打开帖子列表。
2. `openFavoriteDialog()` 展示待收藏列表。
3. 用户点击“开始收藏”。
4. `batchFavoriteOpened()` 获取 `formhash`。
5. 从第一个帖子开始，依次调用 `favoriteThread(tid, formhash)`。
6. 每个请求完成后更新对应行状态。
7. 等待 `CONFIG.FAVORITE_DELAY_MS` 后处理下一个帖子。
8. 全部完成后显示统计结果。

### 3.2 当前问题

- 收藏速度慢，帖子多时等待时间明显。
- 任务没有并发能力，网络空闲时间较多。
- 进度显示偏向“当前第几个”，不能准确表达并发状态。
- 某个请求耗时较长时，会阻塞后续所有帖子。

## 4. 需求范围

### 4.1 本次需要修改

- 修改 `batchFavoriteOpened()` 的执行模型。
- 新增并发队列逻辑。
- 新增或复用并发配置项。
- 优化收藏进度显示。
- 保持每行收藏状态实时更新。
- 保持任务完成后的最终统计。

### 4.2 本次不需要修改

- 不修改帖子打开记录的采集逻辑。
- 不修改 `favoriteThread()` 的请求协议，除非并发改造必须小幅适配。
- 不修改当前帖子页自动登记逻辑。
- 不修改 UI 整体风格。
- 不改动收藏页管理、用户主题页管理、搜索页筛选等无关功能。

## 5. 功能需求

### 5.1 并发收藏队列

批量收藏应使用受控并发队列执行。

建议默认并发数：

```text
3
```

执行规则：

- 同时最多运行 `N` 个收藏请求。
- 任意一个请求完成后，立即补上下一个待处理帖子。
- 所有帖子处理完成后，任务结束。
- 不应一次性对所有帖子发起请求。

### 5.2 并发配置

应新增配置项：

```text
FAVORITE_CONCURRENCY
```

建议默认值：

```text
3
```

可选扩展：

- 在设置弹窗中增加“批量收藏并发数”选项。
- 可选值建议为 `1`、`2`、`3`、`5`。
- 默认选择 `3`。
- 如果用户担心稳定性，可以改成 `1`，等同于串行。

### 5.3 请求节流

即使使用并发，也应保留轻量节流，避免瞬间补队列过快。

建议策略：

- 每个 worker 完成一个任务后，等待一个较短延迟再取下一个任务。
- 可复用 `CONFIG.FAVORITE_DELAY_MS`，或新增更短的并发间隔配置。

建议默认间隔：

```text
200ms - 500ms
```

### 5.4 状态统计

任务执行中应实时展示以下信息：

- 总数
- 已完成数
- 运行中数量
- 待处理数量
- 收藏成功数
- 已收藏数
- 失败数

示例：

```text
进度 8/30，运行中 3，成功 5，已收藏 2，失败 1
```

任务结束后显示：

```text
完成：成功 18，已收藏 10，失败 2
```

### 5.5 行状态显示

每个帖子行应显示独立状态。

状态包括：

- 待收藏
- 收藏中
- 收藏成功
- 已收藏
- 收藏失败

建议颜色：

- 收藏中：蓝色或橙色
- 收藏成功：绿色
- 已收藏：灰色
- 收藏失败：红色

### 5.6 按钮状态

点击“开始收藏”后：

- 开始按钮禁用。
- 按钮文案改为“收藏中...”。
- 刷新列表按钮可以保留，但建议任务中禁用，避免列表和任务状态不一致。

任务完成后：

- 开始按钮恢复可点击。
- 文案恢复为“开始收藏”或“重新开始”。
- 弹出提示“批量收藏完成”。

### 5.7 错误处理

单个帖子收藏失败时：

- 不应中断整个任务。
- 对应行显示失败原因。
- 失败计数加一。
- 队列继续处理后续帖子。

全局错误场景：

- 无法获取 `formhash`：任务不启动，提示用户确认已登录。
- 网络异常：该帖子记为失败。
- 返回结果无法识别：该帖子记为失败，并显示“结果未知”或原始错误摘要。

### 5.8 防重复执行

任务运行中再次点击开始按钮不应重复启动任务。

可通过以下方式实现：

- 复用当前按钮禁用逻辑。
- 新增任务运行状态，例如 `STATE.favoriteOpenedRunning`。

### 5.9 并发完成顺序

并发执行时，完成顺序可能和列表顺序不同，这是允许的。

但 UI 中每个帖子行必须正确更新到对应 `tid`，不能因为完成顺序不同导致状态错行。

### 5.10 可选取消功能

本次可以不强制实现取消功能。

如果实现取消，建议规则：

- 取消后不再启动新的待处理任务。
- 已经发出的请求等待自然完成。
- 完成后不再弹出“全部完成”，而是显示“已取消”。

## 6. 非功能需求

### 6.1 性能

- 不允许一次性发起所有收藏请求。
- 并发数默认不能过高。
- UI 更新应轻量，不要在每个状态变化时重建整个弹窗。
- 只更新对应行状态和底部进度文字。

### 6.2 稳定性

- 并发任务中任何单个请求失败都不能影响其他请求。
- 任务完成统计必须准确。
- 重复 tid 应由 `getOpenThreads()` 去重后再进入队列。

### 6.3 兼容性

- 保持当前 `favoriteThread(tid, formhash)` 的返回格式兼容：
  - `success`
  - `exists`
  - `error`
- 保持“移除”按钮功能。
- 保持“清理打开记录”功能。
- 保持工具栏中的打开帖子数量统计。

### 6.4 用户体验

- 用户能明显感知收藏速度提升。
- 任务执行中应看到实时进度。
- 失败项应能在列表中直接看到。
- 完成后给出清晰汇总。

## 7. 建议技术方案

### 7.1 并发 worker 模型

建议使用多个 worker 共享一个 `nextIndex`。

伪流程：

```text
nextIndex = 0
finished = 0
success = 0
exists = 0
failed = 0

启动 concurrency 个 worker

每个 worker:
  取 nextIndex 对应的帖子
  nextIndex + 1
  如果没有帖子，结束 worker
  标记该行为“收藏中”
  调用 favoriteThread()
  根据结果更新该行
  更新统计
  等待短延迟
  继续取下一个帖子

所有 worker 完成:
  恢复按钮
  显示最终统计
```

### 7.2 推荐新增配置

```javascript
FAVORITE_CONCURRENCY: parseInt(localStorage.getItem('sht_favorite_concurrency') || '3', 10),
FAVORITE_WORKER_DELAY_MS: parseInt(localStorage.getItem('sht_favorite_worker_delay') || '300', 10)
```

如果不希望增加设置项，可以先作为常量写入 `CONFIG`。

### 7.3 推荐新增函数

```text
updateFavoriteBatchProgress(progress, stats)
runFavoriteWorker(queue, context)
getFavoriteConcurrency()
```

也可以直接在 `batchFavoriteOpened()` 内部实现，避免过度抽象。

## 8. 验收标准

### 8.1 基本功能

- 打开多个帖子后，点击“收藏打开帖子”可以看到帖子列表。
- 点击“开始收藏”后，多个帖子会同时进入“收藏中”状态。
- 并发数量不超过配置值。
- 全部处理完成后，显示最终统计。

### 8.2 状态正确性

- 收藏成功显示为成功。
- 已经收藏过的帖子显示为已收藏。
- 请求失败的帖子显示为失败。
- 统计中的成功、已收藏、失败之和等于总数。

### 8.3 稳定性

- 任务运行中不会重复启动第二个任务。
- 单个帖子失败不会中断整个任务。
- 关闭部分帖子页后，不影响已经读取到弹窗里的收藏任务。
- 打开记录清理功能不受影响。

### 8.4 回归验证

- 单个当前帖子收藏功能正常。
- 工具栏“打开帖子”数量统计正常。
- 收藏打开帖子弹窗的“移除”按钮正常。
- 清理打开记录功能正常。
- 其他批量功能、预览功能、自动翻页功能不受影响。

## 9. 风险点

### 9.1 网站请求限制

并发过高可能触发网站限制、请求失败或响应异常。因此默认并发数不宜超过 3。

### 9.2 formhash 失效

如果任务运行期间 `formhash` 失效，可能导致多个请求同时失败。需求中暂不要求自动刷新 `formhash`，但应准确显示失败。

### 9.3 UI 状态错位

并发完成顺序不固定，必须通过 `tid` 定位行状态，不能依赖当前处理顺序。

### 9.4 重复点击

如果没有运行锁，用户可能重复点击开始按钮，导致同一批帖子被重复请求。需要保留按钮禁用并建议增加状态锁。

## 10. 开发建议

建议按以下顺序开发：

1. 在 `CONFIG` 中新增并发数配置。
2. 重写 `batchFavoriteOpened()` 为并发 worker 队列。
3. 增加运行中状态和进度统计。
4. 保持 `setFavoriteRow()` 按 `tid` 更新行状态。
5. 测试 1 个、3 个、10 个、30 个帖子场景。
6. 测试已收藏、收藏成功、失败混合场景。
7. 根据稳定性决定是否把并发数暴露到设置弹窗。

## 11. 优先级

优先级：中高。

原因：

- 当前串行实现稳定但效率低。
- 并发改造可以明显改善大量打开帖子时的使用体验。
- 改动范围集中在批量收藏打开帖子逻辑，风险可控。
